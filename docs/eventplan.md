Repository: JRAdams472/LENA2. This is a modular Go monolith (Echo + graphql-go BFF + PostgreSQL via sqlc/pgx). Each domain owns its own PostgreSQL schema; cross-domain SQL joins are PROHIBITED — the BFF assembles cross-domain data via service interfaces. Follow the exact conventions of the existing `internal/mealplan` module.

GOAL: Add a new "food event" (party/gathering) feature that lets a user combine multiple meals (lunch, dinner, or all meals of a day) into a single event, and assign recipes to be delivered/served at specific absolute time slots with quarter-hour (15 min) or half-hour (30 min) granularity. A future "event timeline" (scheduling every prep/cook step of every recipe) is EXPLICITLY OUT OF SCOPE for this deliverable, but the schema must be designed so it can be computed later without a breaking migration.

Add an index on `(user_id, event_date)`.
